Test Levels by Scope

Unit Tests

Test individual functions/classes in isolation using tools like Jest, Vitest, Catch2, or JUnit.

Integration Tests

Verify multiple modules or services work together (database + API interactions).

Component Tests

UI components tested in isolation using React Testing Library or Storybook interaction tests.

Contract Tests

Verify API producer/consumer agreements using tools like Pact.

End-to-End (E2E) Tests

Full user flows through the real system using Playwright or Cypress.

System Tests

Test the entire application as a whole in a production-like environment.

Smoke Tests

Quick sanity checks that the build basically works before deeper testing.

Regression Tests

Re-run test suites to catch previously fixed bugs reappearing.

Acceptance Tests / UAT

Validate against business requirements, often performed by stakeholders.

Behavior-Driven & Specification Styles

  • Gherkin/BDD Tests– Given/When/Then scenarios using Cucumber, SpecFlow, or Behave
  • Property-Based Tests– Generate random inputs to test invariants (QuickCheck, fast-check, Hypothesis)
  • Snapshot Tests– Compare output against stored references (UI markup, serialized data)
  • Approval/Golden-Master Tests– Human-approved baseline outputs for legacy code

Non-Functional Testing

Performance Tests

Measure response times and throughput under normal conditions.

Load Tests

Evaluate behavior under expected traffic using k6, Gatling, or JMeter.

Stress Tests

Push systems beyond capacity to identify breaking points.

Soak/Endurance Tests

Long-running load scenarios to detect memory leaks and degradation.

Security Tests

SAST, DAST, dependency scanning, and penetration testing.

Accessibility Tests

Validate WCAG/EN 301 549 compliance using axe-core, Pa11y, or manual screen-reader testing.

Usability Tests

Watch real users perform tasks to identify UX friction.

Compatibility Tests

Verify functionality across browsers, devices, and operating systems.

Localization/i18n Tests

Validate translations, RTL layouts, and date/currency formats.

Chaos Engineering

Inject failures in production-like systems to test resilience.

Test Quality & Robustness Techniques

  • Mutation Testing– Introduce code mutations to verify tests actually catch bugs (Stryker, PIT)
  • Fuzz Testing– Feed malformed/random input to find crashes and vulnerabilities
  • Flaky Test Detection– Identify non-deterministic tests through repeated runs
  • Visual Regression Testing– Pixel/DOM diffing of UI changes (Percy, Chromatic, Playwright screenshots)

Approaches & Methodologies

  • TDD (Test-Driven Development)– Write tests first, then implement code to pass
  • BDD (Behavior-Driven Development)– Define behavior with stakeholders before implementation
  • ATDD (Acceptance Test-Driven Development)– Acceptance criteria drive development decisions
  • Exploratory Testing– Unscripted, experience-driven manual investigation
  • Risk-Based Testing– Prioritize test effort by likelihood and impact of failure
  • Shift-Left Testing– Move testing earlier in the development lifecycle

QA Procedures & Processes

  • Test Planning– Define scope, strategy, resources, and schedule
  • Test Case Design– Use equivalence partitioning, boundary value analysis, decision tables, state transitions
  • Code Review / Peer Review– Manual inspection of code before merge
  • Static Analysis & Linting– Automated code checks using ESLint, SonarQube, etc.
  • Defect Triage– Prioritize and assign bugs for resolution
  • Release/Regression Checklists– Gated sign-off procedures before deployment
  • Traceability Matrix– Map requirements to test cases for coverage
  • Canary Releases & Feature Flags– Gradual rollout as testing-in-production
  • Post-Incident Reviews– Blameless postmortems to learn from production failures

Quality Metrics

Metric Description
Test Coverage Line, branch, function, or statement coverage (aim for meaningful coverage, not just high numbers)
Mutation Score Percentage of code mutations killed by your test suite
Defect Density Bugs found per thousand lines of code (KLOC) or per feature
Defect Escape Rate Percentage of bugs found in production vs. caught in testing
MTTR / MTBF Mean Time To Repair / Mean Time Between Failures
Flakiness Rate Percentage of test runs failing non-deterministically
Test Execution Time Total suite duration (impacts CI feedback loops)
Cyclomatic Complexity Code complexity as a proxy for testability and maintainability
Code Churn Frequently changed files often correlate with defects
DORA Metrics Deployment frequency, lead time, change failure rate, MTTR
